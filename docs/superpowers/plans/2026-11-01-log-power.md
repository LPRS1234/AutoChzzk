# 통나무 파워 표시 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan in the current workspace.

**Goal:** 등록 채널 이름 옆에 선택한 Chrome 프로필의 치지직 계정이 보유한 통나무 파워를 표시한다.

**Architecture:** 확장 프로그램이 치지직 웹에서 사용하는 읽기 전용 `/service/v1/channels/{id}/log-power`의 `content.amount`를 로그인 세션으로 조회한다. 기존 인증된 로컬 연결로 채널별 숫자 또는 null만 전달하고 Tkinter 메인 스레드에서 반영한다.

**Tech Stack:** Python/Tkinter, Chrome Manifest V3, unittest, Node test runner. 새 의존성 없음.

## Global Constraints

- 기존 저장 데이터와 탭 제어 형식은 유지하고, 선택된 프로필에만 조회할 등록 채널 목록을 돌려준다.
- 60초 간격으로 최대 4개씩 조회한다. 연결 해제·조회 실패·잘못된 응답은 `통나무 —`로 표시하고 실제 0은 `통나무 0`으로 표시한다.
- 쿠키는 Chrome 안에서만 사용한다. 통나무 수치는 디스크에 저장하지 않는다.
- 앱 2.5.0, 확장 프로그램 2.2.0. 배포와 Release 생성은 수행하지 않는다.
- 기존 구조가 있는 확장 프로그램 조회 방식을 사용한다. DOM에서 화면 문구를 읽는 방법은 프로필 팝업을 열어야 하며 페이지 구조에 의존하므로 사용하지 않는다.

## Review Focus

프로필 전환과 연결 만료, 로그아웃, 0과 조회 실패 구분, 안전하지 않은 숫자/과도한 목록 거부, 기존 확장 프로그램과의 호환성을 검증한다.

### Task 1: 확장 프로그램과 로컬 서버 연결

- [x] 숫자 전달, 실패와 만료, 프로필 격리, HTTP 입력 검증, 조회 간격과 병렬 제한 테스트를 먼저 추가하고 실패를 확인한다.
- [x] ChromeTabState의 기존 clients 구조를 유지하며 별도 메모리에 통나무 보고와 요청 채널을 관리한다. 요청의 logPowers와 응답의 logPowerChannelIds를 선택 필드로 추가한다.
- [x] background.js에 읽기 전용 조회와 메모리 캐시를 추가하고 manifest에 api.chzzk.naver.com 호스트 권한을 추가한다.
- [x] 관련 Python/JavaScript 테스트가 통과하는지 확인한다.

### Task 2: 채널 이름 옆 표시와 검증

- [x] 실제 Tkinter 행에서 숫자/0/미확인 표시와 프로필 전환 후 표시 갱신을 검증한다.
- [x] 기존 2초 UI 갱신에 표시를 연결하고 등록 채널 변경 시 조회 대상도 갱신한다.
- [x] 버전, README, 확장 안내, 변경 내역을 맞춘다.
- [x] 전체 Python/JavaScript 테스트 및 Windows 패키징을 검증한다. 실제 로그인 세션 검증 가능 여부를 보고한다.

## 검증 기록

- Python unittest 147개 및 Node 테스트 23개 통과. 조회 지연 중 탭 명령 처리와 프로필 해제 후 진행 중 결과 폐기도 확인했다.
- PyInstaller Windows GUI 빌드 성공. 제품 이름·설명·2.5.0 버전과 저작권 항목 없음도 확인했다.
- 합성 데이터의 실제 Tkinter 창에서 숫자와 0 표시 및 최소 너비 레이아웃을 확인했다. 독립 코드 리뷰에서 중요 결함이 발견되지 않았다.
- 실제 로그인 세션 조회는 브라우저 연결 도구가 없어 확인하지 못했다. 기존 설치 앱은 변경하지 않았으며 설치·배포·Release 생성은 수행하지 않는다.
- Ruling: 저장 채널 256개 초과 시 일부 채널이 조회 대상에서 제외되는 기존 통신 크기 한계를 README에 명시했다.
